# GitHub Actions broker sync
No local Python server is required for this workflow. The legacy Python files remain optional.
1. Prefer a private repository. Review all workflow and frontend code, restrict write access, enable MFA and protect branches. In Settings > Environments create broker-sync, restrict deployment to refactor/modular-architecture and require approval if supported by your plan. Do not run untrusted changes with secrets.
2. Add environment secrets KITE_API_KEY, KITE_ACCESS_TOKEN and BROKER_EXPORT_PASSWORD (unique randomly generated password, at least 24 characters). Never use a broker password as the export password.
3. Obtain a current access token using the official Kite authentication flow. Alternatively set KITE_API_SECRET and KITE_REQUEST_TOKEN as protected environment secrets. Open https://kite.zerodha.com/connect/login?v=3&api_key=YOUR_API_KEY in your browser, authenticate and extract request_token from your registered callback URL. Update the request-token secret immediately before running; it is short-lived and single-use. The runner exchanges it for an access token in memory, without printing or exporting it. Delete the request-token secret after use. Remove it before using the access-token alternative. Never paste tokens in workflow inputs, chat or source code. Approval delays can cause expiry; renew and retry. Broker tokens may allow trading even though this workflow only calls holdings endpoints.
4. The workflow must exist on the default branch before GitHub permits manual workflow dispatch. Review and merge the workflow as appropriate, then select refactor/modular-architecture when running it. The job explicitly rejects other branches.
5. Download the encrypted artifact, unzip, enter the export password in Import/Data and select broker-encrypted.json. No holdings are inserted into the ledger. Delete the artifact when done.
GitHub runners process plaintext broker data and secrets in memory. Encryption protects the exported artifact, not against a malicious workflow or compromised runner/frontend. Do not use this design if strict device-only processing is required. No live broker authentication or end-to-end test has been performed. Paytm, automatic login, automated artifact delivery and reconciliation remain pending.
